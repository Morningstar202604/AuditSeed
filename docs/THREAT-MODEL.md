# Threat Model — AuditSeed v0.0.1

AuditSeed 的承诺是**让历史可验证**，不是"绝对安全"。本文档诚实列出防什么、不防什么。

## 防得住（在本版本的设计边界内）

| 威胁 | 机制 |
| --- | --- |
| 事后修改/伪造链条目 | 逐条 SHA-256 链式哈希（`prev/hash`），`verify` 全链重算并定位首个断点 |
| 静默删除条目 | `seq` 连续性校验；文件级删除在 verify 中表现为 seq 断裂 |
| 模型谎报"没改过某文件" | hook 硬采集（客户端触发，模型不可绕过）+ git 对账双重兜底 |
| "为什么改"丢失 | 声明仪式（task_open.reason）与事件同链哈希绑定 |
| 崩溃误判为篡改 | 撕裂行分类：链接续接 → debris（信息性）；断链 → fatal |
| 并发追加互相覆盖 | O_EXCL 单写者锁 + 陈旧锁回收（有界重试） |

## 防不住（明确边界）

1. **本机全权攻击者**：能读能删整个 `~/.auditseed` 的攻击者可以销毁证据。
   哈希链对"有重算能力的攻击者"只提供**篡改可检测性**（任何改动导致断链），
   不提供不可销毁性。缓解：0.1 起提供链头外锚（粘贴进 PR / CI artifact /
   定期推远端只读镜像）。
2. **无 hook 客户端的采集缺口**：规范不强制 hook。无 hook 的客户端只有 git
   对账兜底，覆盖率报告会如实呈现缺口（这正是设计：**缺口可见，而非隐藏**）。
3. **对话通道外泄**：模型把代码"讲"出去（聊天/联网工具）不在采集范围。
   这属于 AgentSeed/网络层职责。
4. **记录者与行为者同机**：信任根是本机用户账号。企业级不可抵赖需要远端
   公证（0.2 路线）。
5. **审计员视角的"自证"**：本机哈希链是"完整性自证"，审计师可能要求外部
   锚点。0.1 的 anchor 事件 + 0.2 的只读镜像为此设计。
6. **敏感内容入链**：diff 统计入链，但命令文本与路径可能含敏感串。0.1 提供
   脱敏规则；当前建议本地磁盘加密。

## 与 AgentSeed 的分工

- AgentSeed：**代码正确性**门禁（未定义符号 / 幻觉 / 实跑验证）——防 agent 说谎。
- AuditSeed：**过程可追溯**（谁/何时/改了什么/为什么/结果）——让改动可问责。
- 联动：AgentSeed 的 verify 结论可作为 `verify` 事件进入审计链。
